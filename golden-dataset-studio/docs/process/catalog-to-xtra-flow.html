From catalog to a finished xtra extract

How one catalog, resource type and property moves from the Kanban board through the subject matter experts' rule loop, becomes a golden dataset with a first score against xtra, and then drives the engineering loop on xtra extract until it scores 100%.

The unit that moves through the flow:
catalog×resource type×propertye.g.WVU × Credential × ceterms:description
Subject matter experts, in Golden Dataset Studio Engineering, in the xtra CLI Studio feature still to build

The two loops and the handoff

Loop A · SMEs

Label the property with a rule

  1. Annotate records: add corrections and suggestions.
  2. Generate improved rules.
  3. Reapply the rule to every page in the catalog.
  4. Check the result. Where the rule is wrong, annotate those records and go round again.

Exit: the SMEs judge the rule correct on 100% of records. They approve it and publish the property. Each value carries approval: human or rule.

Handoff

Golden set + first score

Publishing puts one property for one resource type in one catalog into xtra-golden-sets. Then the catalog needs a score:

  • If the baseline xtra runs on the catalog without crashing, the SME clicks Score in the Studio, which runs the baseline extract and scores it against the golden set.
  • If it doesn't, engineers build a baseline that runs end to end first, then the score runs.

The SMEs hand off both, golden set and first score, and move the card to Scoring + Eval.

Engineers never edit golden values. If one looks wrong, they raise it and the SMEs re-review it in the Studio and republish.

Loop B · Engineering

Fix the extractor until it matches

  1. Start from the handoff score.
  2. Diff xtra extract output against golden and group the errors by cause.
  3. Change the extractor for the biggest cause.
  4. Re-run and score this catalog and every other golden set.

Exit: 100% on this catalog × resource × property, and no drop on any other golden set. Tag the CLI version and mark it done.

The board moves one card per catalog, but the flow finishes one catalog × resource × property at a time. The milestone covers five resource types (Course, Learning Program, Credential, Competency/Framework, Assessment Profile), so a catalog card would sit in a column while its properties are spread across several steps. See the last open question below.

Rules that keep the numbers honest

  • A card moves to Scoring + Eval only with both a published golden set and its first score, recorded before any code changes for that catalog.
  • Every Loop B run scores all golden sets, not only the target, so a fix for one catalog cannot quietly break another.
  • Golden values change only through the SMEs in the Studio. Engineering disputes them; it does not edit them.
  • "Done" names a CLI version. A later change that drops a done cell below 100% reopens it.

Open research question: generalization

Reaching 100% on a catalog we tuned on says little about catalogs we haven't seen. We don't yet know how to quantify how well xtra generalizes for a given field across other catalogs. That needs its own dedicated time, probably once a few catalogs have been through both loops. Ideas to start from:

  • Treat each catalog's handoff score as a first look at an unseen catalog, and watch whether it rises catalog after catalog.
  • Seal one golden catalog that engineering never debugs against, and score it only at tagged releases.
  • Spot-check small random samples on Backlog catalogs that have no golden set.

Still to decide

  • How a new catalog gets into the Studio. Today its five catalogs are hard-coded (catalogs.py); registering one from its crawl output needs building.
  • What the Studio's Score button runs: which xtra version counts as the baseline, and where the run and its score are kept.
  • What counts as a match for 100%: exact text, or normalized (whitespace, casing, list order).
  • Spot-check sample size, and who on the SME side does it.
  • How the board tracks progress below the catalog: sub-issues per resource type, or the existing Benchmark Status field listing which properties are done.
