How the Studio works

Open questions

Each one changes what gets built. The mockup assumes the recommended answer.

Q1Once a catalog's added, where do its first rules come from?
New catalogs have no v2 rules.json to import. Should they start with an empty ruleset, a copy of the rules from another catalog on the same platform (e.g. CourseLeaf → Marshall/WVU), or a “write the first rules” prompt for Claude Code?
My suggestion: offer “Start from Marshall's rules (same platform)” whenever the platform matches, and otherwise a Claude prompt to bootstrap them.
Q2Can you add crawls that hit the page limit or stopped early?
Allow them with the amber or red chip showing, allow only complete ones, or let you add them with a warning that a golden dataset has to be complete (§0)?
Mockup: they can be picked but carry a chip. Confirming one adds “This crawl isn't complete, so the golden dataset won't be either.”
Q3Who's allowed to add a catalog?
Profiles now have roles (subject matter expert / engineer). Should anyone be able to, only engineers, or anyone for already-crawled catalogs but only engineers for a new crawl?
Q4What about a newer crawl of a catalog that's already in the Studio?
Right now those rows say “Already added”. Should they say “Newer crawl available (Oct 25)” and let you switch to it? That brings up re-extraction and moving annotations across crawls, which is probably its own spec section.
Recommend: out of scope for this round. Show the newer date in the row and nothing more.
