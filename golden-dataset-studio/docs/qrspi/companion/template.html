§3 · Workflow

The review loop

The loop has three stages:

  1. Review. Jared reviews one rule's results, row by row, in the Studio.
  2. Improve. Claude Code improves the rule on Eric's laptop and checks it against Jared's verdicts.
  3. Approve. Jared compares the new version with the old one, and approves it or annotates again.

Press Follow GEOG222 to watch one real Description go through the loop. Jared marked it wrong because it starts with "Prerequisite: …", and Claude's rule v2 fixed it.

Steps are boxes and questions are hexagons. Dotted arrows loop back. Click a step to see what it reads, what it writes, and a real example.

§11 · Sequence of work

What runs in parallel, and what has to wait

Columns show order and overlap, not dates. The spine is W0 → W2 → W3 → (W4, W5) → W6 → W7, because each step needs the previous one's files. The page pane (W1) only shares the storage layer, so it runs alongside from the start. v2's speed fixes are already done in their own Superset workspace.

M1 · Data in placegolden-datasets sync, init, import-v2, extract and check work for AVC. golden-datasets sql answers "every value of rule X".
M2 · Thin sliceThe Rules tab shows ceterms:description on AVC with the full page pane. Annotations are recorded.
M3 · The loop closesPrompt → Claude → rule try → publish → Compare shows the real "prerequisite in Description" fix.
M4 · EverythingAll five catalogs, every in-scope rule, golden publication with lineage.
