## 6. Spec feedback

Where the spec's model was awkward or wrong while building this data, and what the prototype did instead. Each item says
**what I did** and **why**. Numbers are from the AVC example above.

### Keys and hashes

1. **`content_hash` over "definition + the definitions it depends on" re-versions rules nobody touched.** Followed as written
   (transitive: field → locator → page rules). Consequence: any locator or page-rule edit gives every field rule beneath it a new
   hash, hence a new version, and §4.3 resets each to *in review*, so approvals are lost even when values don't change. Also
   `content_root` is a ruleset *setting*, outside every hash, yet it changes every rule's behaviour. **Suggest:** `content_hash` =
   the rule's own definition (identity, drives versions and approvals). Add an `input_hash` per rule *in the extraction*:
   definition + dependencies + `content_root` (drives reuse/rerun). Re-approval can then be triggered by "values changed",
   not "a dependency changed".
2. **`depends_on` of a field rule = its locator only.** The code rule only feeds `course_key`, not the value, so it isn't a
   dependency of the definition. The rerun scope still reruns it (§4.3). I asserted its rerun reproduces rs-0001 exactly, then
   kept rs-0001's rows. Since `course_key` already sits on `occurrences`, "rerun the code rule" can become "copy `course_key`
   from occurrences".
3. **`course_key` is stored twice** (occurrences and matches). Kept both for convenient queries; `check_integrity.py` enforces
   equality. Prefer occurrences only, joined when needed.
4. **`signals` PK `(extraction, target, signal)`: "target" is not a column.** Decomposed into `target_kind, rule_id,
   occurrence_key, value_index, page_stem`. Page signals like `page-not-classified` have `rule_id = null`, so the PK has nullable
   parts. Spec should list the columns.
5. **History signals can't live in the immutable `signals.parquet`.** They depend on the mutable annotation log. Computed at
   query time (server and Compare): `changed-since-correct`, `previously-wrong`, `fixed-since-wrong`, `verdict carried from vN`.
   Spec §2/§4 should say `signals.parquet` holds value / cross-row / page signals only. The same applies to **signal
   thresholds** in ruleset settings: changing one changes signals without changing any rule. Define whether that's a
   settings-only ruleset version with a signals-only recompute.
6. **"Byte-identical" copies → row-identical.** The `extraction` column is not stored in the rows (the folder implies it), so
   copied rows are identical, verified by `EXCEPT` in both directions. The files differ, because a file holds copied *and*
   rerun rows. Spec should say "row-identical".
7. **Extraction PK `(crawl, ruleset_version)`** forbids re-extracting the same ruleset (engine fix, new signal code).
   Kept as written; suggest an independent `extraction` id with `(crawl, ruleset_version)` as a non-unique attribute.
8. **Document-root css paths are long:** AVC's content root alone is 9 steps,
   `html > body:nth-of-type(1) > app-root:nth-of-type(1) > … > div:nth-of-type(4)`. That makes every `occurrence_key` about
   200 characters and the prompt unreadable (the prototype's prompt points at `golden-datasets pages get <stem> --match <rule>` instead).
   They **do** resolve in a browser: 652/652 match paths and 202/202 occurrence paths across 60 sampled pages in Chromium, text
   matches 652/652 (`check_paths_browser.py`). **Suggest:** keep the document-root path on occurrences. Store match `css_path`
   relative to its occurrence, or store both.
9. **Character offsets have v2 semantics:** BeautifulSoup text, `<br>` → `\n`. That isn't the browser's `textContent`: offsets
   were exact for 606/652 matches in Chromium. The UI falls back to a text search. The spec should define offsets in
   `textContent` terms (what highlight capture produces), or define a normalization.

### Rules and rulesets

10. **Page rules renamed** (`label-course-page` → `course-page`, `label-program-page` → `program-page`,
    `label-course-on-program-page` → `program-page-with-courses`), because §2 bans "label". The v2 id is kept in
    `imported_from.v2_rule_id`. Field rule ids are unchanged.
11. **The locator really is shared:** each locator was built from one stub rule's `repeat`, and `import-v2` asserts every other
    field rule under it carries the identical `scope/repeat/repeat_filter`. Confirms research B10.
12. **`pane_css` from v2 is wrong for full-page rendering.** It hides every `svg` (AVC's logo and icons) and restyles `.row`.
    It also doesn't open AVC's accordions, which are closed by `.accordionheader{height:56px;overflow:hidden}`, so stubs on program
    pages were invisible. Ruleset v1's settings carry a reviewed reveal sheet scoped to `content_root`; v2's is kept as
    `pane_css_v2`. A settings-only change like this needs a defined publish path (new ruleset version, nothing rerun).

### Annotations and the v2 import

13. **Rule approval needs an event type.** §4.3 talks about "an `approve` event", but the annotation schema only has verdicts.
    Used one log with `type: verdict | approve`, `target.kind = rule`. Constant/URL rules got 5 approve events authored by
    `golden-datasets import-v2` (a machine author; the spec should allow that).
14. **Target kinds used:** `match` (field rules), `occurrence` (locators, UI only), `page` + `rule_id` (page rules), and `page`
    with `rule_id = null` (v2 page flags → `question`). The FK "→ rule_id" must allow null.
15. **Jared's 7 `wrong` verdicts on `program-page-with-courses` look like a vocabulary artifact.** v2 labelled program pages
    "Course" to mean "this page lists course stubs". Jared read it as "this page is a course": he rejected it and added
    Credential/Competency labels. Imported as instructed, so that rule shows *needs work*, possibly for the wrong reason. Ask
    Jared, or import label rejects as `question` with his note.
16. **16 "missing" labels (Credential, Competency) have no page rule** in scope → skipped (counted in the import tally).
17. **reject + missing can have different authors** (GEOG222: Seth's missing, Jared's reject). One `wrong` was written with the
    rejecter as author and both decisions in `imported_from.decisions[]`. The spec should say which author wins.
18. **No standalone `missing` survived the import.** All 5 pair with a reject. Define `missing` as "the rule produced no value
    (status empty/no_match) but the page has one", and `wrong` + `expected` as "the value is wrong". Otherwise the two overlap.
19. **`expected` located automatically:** every imported expected text was found inside the matched element
    (`located_by: "golden-datasets import-v2 text search"`), so imports get the same `css_path` + offsets + quote as highlight capture.
20. **Notes:** 4 of 21 v2 notes attach to in-scope annotations. The other 17 are on Credit Unit Type and are dropped.

### Signals

21. **Shape outlier needs a dominance test.** Applied naively to titles it flagged 296 course names. It's now applied only when
    the rule's most common shape covers ≥ 50% of values (codes yes, titles no). Thresholds are in `settings.signals`.
22. **`page-not-classified` fires on 129 AVC pages:** department pages, `allcourses` (1,022 codes), CLEP/AP tables. That's the
    D4 caveat in numbers: it needs a per-catalog allow-list or a higher threshold to be useful.
23. **`contains-label-text` was the most useful signal.** 547 → 273 after v2. It also exposed what Jared hadn't seen: 174
    "Advisory:" and 199 "Limitation on Enrollment:" lines.

### The iteration itself (evidence for `golden-datasets rule try`)

24. The first course-description v2 draft dropped Advisory/Limitation lines too. The comparison flagged **4 descriptions Jared
    had marked correct** that changed (ACCT199, AERO199, CFE114, NS922L), so the published v2 only drops requisites:
    5 fixed / 0 still wrong / 0 newly wrong, 278 changed. That is exactly the scorecard `golden-datasets rule try` must print before
    publishing.

### Golden publication

25. **Learning Type has no CTDL term**, so `(…, ctdl_property, …)` can't be the lineage PK. Used `property` (template name) +
    `ctdl_term` (nullable) in both `courses.json` and `lineage.parquet`.
26. **`golden_id` = `course_key`** works for AVC, but not for Marshall/WVU (~190 codes with different entries). The spec
    needs a golden-id rule.
27. **The example publication bypasses the approval gate** (12 of 17 rules not approved). `publication.json` records
    `approval_gate.all_rules_approved: false`.

### Storage layout

28. **Assets split into two tables:** `assets/page_assets.parquet` (crawl, page_stem, url) for page → asset references, and
    `assets/assets.parquet` (crawl, url → sha256, status, type, bytes, referenced_by), plus `files/<sha256>`. The spec's
    single `assets/manifest.parquet` with PK (crawl, page_stem, url) has no row for fonts referenced from CSS (no page). AVC:
    7,335 page → asset rows, 18 assets, 645 KB. The prototype's page pane still loads CSS from the live site, as asked.
29. **Pages:** `<catalog>/<crawl>/pages` and `crawl.json` are symlinks into the mirror. `pages.parquet.html_path` is relative
    to the root, so the same row works for a local root or an Azure prefix.
30. **UI writes:** the prototype's UI appends annotations to a scratch JSONL, never to the example root, so the integrity
    output above stays reproducible.

### Changes from Eric's review rounds (data model impact)

31. **Verdict `unsure` is renamed `question`** ("question for the institution"). Jared is the domain expert. What he
    sometimes needs is an answer from the college itself. Spec §2's verdict list should read
    `correct · wrong · missing · question`. A plain comment (`type: comment`) is a separate annotation type, with no verdict.
32. **`missing` belongs only to rules that find things.** It applies to record locators (a missed course: `target.kind =
    occurrence`, `occurrence_key = null`, `expected` = the selected course block) and page rules (a missed page). Field
    rules have only correct / wrong: an empty value the page does have is `wrong` + `expected`.
33. **New signal `uncovered-code`.** It flags text that looks like a course code, inside the area where a locator found
    courses (their nearest common ancestor) but outside every found block. AVC: 18 spots on 8 program pages, e.g. "CFE 201
    fulfils CORE 8 Requirements" and "Choose one MATH150 (Total 5)". It needs a location, so `signals.parquet` gained
    nullable `css_path`, `char_start` and `char_end` columns, and these join the signals PK. It replaces the earlier
    `uncovered-pattern`.
34. **`expected.author`.** When a v2 reject and its correction come from different people, the `wrong` verdict's author
    is the rejecter and `expected.author` is the person who typed the expected text (GEOG222: Jared / Seth).
35. **Golden output keeps the `xtra-golden-sets-verified` shape.** One folder per page, `<stem>/<stem>.json` (+ `.html`),
    holding `[{golden_id, fields: [{ctdl_property, property, value, source_url, location}]}]`. Learning Type keeps
    `ctdl_property: null`. `lineage.parquet` adds `page_stem`; its key stays `(publication, golden_id, property,
    value_index)`. That key only works while each course appears on one page in the publication. Including program-page
    stubs or WVU's duplicate course pages would need `page_stem` in the key, or a golden_id per occurrence.
